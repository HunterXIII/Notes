## 1. Что такое сетевой пакет? Из каких основных частей он состоит и какую информацию содержит заголовок?

Сетевой пакет — совокупность данных, передаваемых между устройствами через компьютерную сеть за определённый промежуток времени. Большие данные (файл, страница сайта) режутся на много пакетов, каждый идёт по сети отдельно.

Пакет состоит из двух частей:
- **заголовок** — служебная информация, нужная сети, чтобы доставить пакет;
- **полезная нагрузка** — сами передаваемые данные.

Что лежит в заголовке (на примере IP-пакета):
- IP-адрес отправителя и IP-адрес получателя;
- протокол следующего уровня (TCP, UDP, ICMP);
- длина пакета;
- TTL (время жизни) — сколько маршрутизаторов пакет может пройти, чтобы не крутиться в сети вечно;
- контрольная сумма — для проверки, что заголовок не испортился.

## 2. Чем отличаются кадр, пакет, сегмент и дейтаграмма? На каких уровнях используются эти понятия?

Это одна и та же идея (порция данных), только на разных уровнях модели, и у каждой свой заголовок:
- **кадр** — канальный уровень (Ethernet). В заголовке MAC-адреса. Ходит только внутри одной локальной сети;
- **пакет** — сетевой уровень (IP). В заголовке IP-адреса. Может идти через маршрутизаторы в другие сети;
- **сегмент** — транспортный уровень, протокол TCP. В заголовке порты, номера последовательности, флаги (SYN, ACK и т.д.);
- **дейтаграмма** — транспортный уровень, протокол UDP. Тоже есть порты, но без установки соединения и без гарантий доставки.

Получается матрёшка: сегмент лежит внутри пакета, а пакет — внутри кадра. В Wireshark это видно по дереву: Ethernet II → Internet Protocol → TCP.

## 3. Что такое инкапсуляция и декапсуляция? Последовательность преобразования данных

**Инкапсуляция** — это добавление служебной информации (заголовков) к данным при отправке. Данные идут сверху вниз по уровням, и каждый уровень «заворачивает» их в свой заголовок:

1. Приложение формирует данные (например, команду FTP `USER` с логином).
2. Транспортный уровень добавляет TCP-заголовок (порты) — получается сегмент.
3. Сетевой уровень добавляет IP-заголовок (IP-адреса) — получается пакет.
4. Канальный уровень добавляет Ethernet-заголовок (MAC-адреса) — получается кадр.
5. Физический уровень передаёт кадр по кабелю или радио в виде битов.

**Декапсуляция** — обратный процесс у получателя: уровни снимают свои заголовки снизу вверх (кадр → пакет → сегмент → данные), пока приложение не получит исходные данные.

## 4. Чем модель TCP/IP отличается от модели OSI? Уровни TCP/IP и примеры протоколов

- **OSI** — теоретическая модель из 7 уровней (физический, канальный, сетевой, транспортный, сеансовый, представления, прикладной). Её используют, чтобы объяснять и разбирать работу сети.
- **TCP/IP** — модель, по которой реально работает интернет. В ней 4 уровня: верхние три уровня OSI объединены в один прикладной, а физический и канальный — в уровень сетевого доступа.

Уровни TCP/IP:
- **прикладной** — HTTP, HTTPS, FTP, SSH, DNS, DHCP;
- **транспортный** — TCP, UDP;
- **межсетевой (сетевой)** — IP, ICMP;
- **сетевого доступа** — Ethernet, Wi-Fi, ARP.

## 5. Что такое IP-адрес и MAC-адрес? В чём различие и для чего каждый?

- **MAC-адрес** — физический адрес сетевой карты, задаётся производителем. Пример из работы: `52:54:00:4D:00:69` (виртуальный адаптер QEMU). Нужен для доставки кадров внутри одной локальной сети.
- **IP-адрес** — логический адрес, который назначается узлу в сети (вручную или через DHCP) и может меняться. Пример: `192.168.122.153`. Нужен, чтобы доставлять пакеты между разными сетями (маршрутизация).

Простая аналогия: IP-адрес — как почтовый адрес, по которому письмо идёт через почтовые отделения, а MAC-адрес — как имя получателя, по которому письмо вручают уже на месте.

Поэтому MAC-адрес конечного узла можно увидеть только в своей локальной сети: в глобальной сети мы видим MAC-адрес ближайшего узла (обычно своего маршрутизатора), потому что на каждом маршрутизаторе кадр собирается заново.

## 6. Для чего нужен протокол ARP? Как компьютер узнаёт MAC-адрес другого устройства в сети IPv4

ARP нужен, чтобы по известному IP-адресу узнать MAC-адрес. Без MAC-адреса нельзя собрать Ethernet-кадр, а значит, нельзя ничего отправить даже соседу по сети.

Как это происходит:
1. Компьютер проверяет свою ARP-таблицу (кэш) — может быть, MAC-адрес уже известен.
2. Если нет — отправляет **широковещательный** ARP-запрос всем в сети: «У кого IP 192.168.122.153? Сообщите 192.168.122.239».
3. Все устройства его получают, но отвечает только то, у которого этот IP: «192.168.122.153 — это я, мой MAC 52:54:00:4D:00:69». Ответ отправляется уже напрямую.
4. Компьютер записывает пару IP — MAC в ARP-таблицу и дальше пользуется ей. Посмотреть таблицу можно командой `ip neigh`.

Если адрес находится в другой сети, компьютер узнаёт через ARP MAC-адрес не получателя, а своего шлюза (маршрутизатора).

## 7. Что такое TCP? Функции и установление соединения (Three-Way Handshake)

TCP — транспортный протокол, который сначала устанавливает соединение, а потом надёжно передаёт данные.

Что он делает:
- гарантирует доставку: получатель подтверждает принятые данные (ACK), потерянное отправляется повторно;
- сохраняет порядок: у каждого байта есть номер, получатель собирает данные в правильной последовательности;
- проверяет целостность с помощью контрольной суммы;
- регулирует скорость, чтобы не перегрузить получателя и сеть;
- различает приложения по портам (например, 21 — FTP, 22 — SSH).

Тройное рукопожатие:
1. Клиент → сервер: **SYN** («хочу соединиться», свой начальный номер).
2. Сервер → клиент: **SYN, ACK** («согласен», свой номер и подтверждение номера клиента).
3. Клиент → сервер: **ACK** («подтверждаю»). Соединение установлено, можно передавать данные.

В работе это было видно в Wireshark (рисунок 10). Там же видно, как выглядит сканирование nmap: клиент шлёт много SYN на разные порты, открытые порты отвечают SYN, ACK, закрытые — RST.

## 8. Для чего нужен DNS? Как доменное имя превращается в IP-адрес

DNS переводит доменные имена, удобные человеку (например, `wireshark.org`), в IP-адреса, с которыми работает сеть.

Последовательность:
1. Компьютер проверяет свой кэш и файл `/etc/hosts`.
2. Если ответа нет — отправляет запрос своему DNS-серверу (обычно у провайдера или на роутере). Чаще всего по UDP, порт 53.
3. Если DNS-сервер сам не знает ответ, он идёт по цепочке:
   - спрашивает **корневой сервер** — тот говорит, какой сервер отвечает за зону `.org`;
   - спрашивает **сервер зоны .org** — тот говорит, какой сервер отвечает за `wireshark.org`;
   - спрашивает **сервер домена wireshark.org** — тот отдаёт IP-адрес.
4. DNS-сервер возвращает IP-адрес компьютеру, и оба запоминают ответ в кэше на какое-то время.

## 9. Для чего используется протокол ICMP?

ICMP — служебный протокол для диагностики сети и сообщений об ошибках. Пользовательские данные по нему не передаются.

Примеры:
- `ping` отправляет Echo request и ждёт Echo reply — так проверяют, доступен ли узел и какая задержка (в работе — рисунки 3 и 4);
- `traceroute` использует сообщения «время жизни истекло», чтобы узнать маршрут до узла;
- маршрутизатор отправляет «узел/порт недоступен», если пакет нельзя доставить.

## 10. Что такое Wireshark и для чего он нужен? Задачи в области ИБ

Wireshark — бесплатный графический анализатор сетевого трафика (сниффер). Он перехватывает пакеты на сетевом интерфейсе и показывает их содержимое по уровням: от Ethernet до прикладного протокола.

Задачи в информационной безопасности:
- найти передачу паролей и данных открытым текстом (как с FTP в работе — логин и пароль были видны в командах USER и PASS);
- проверить, что трафик действительно шифруется (SSH — только Encrypted packet);
- обнаружить сканирование портов (много SYN-пакетов с одного адреса за короткое время);
- найти подозрительную активность: неизвестные соединения, обращения к странным адресам, необычно большой объём трафика;
- расследовать инциденты по сохранённой записи трафика (файл .pcap);
- диагностировать проблемы сети: потери, повторные отправки, ошибки.

## 11. Как работает Wireshark? Получение, декодирование и отображение пакетов. Что такое диссекторы?

1. **Получение.** Wireshark через библиотеку захвата (libpcap в Linux, Npcap в Windows) получает копию каждого кадра, который проходит через выбранный сетевой интерфейс. Для захвата нужны права администратора (или членство в группе `wireshark`).
2. **Декодирование.** Каждый кадр разбирается по уровням с помощью диссекторов: сначала Ethernet, по его полю понятно, что внутри IP; IP говорит, что внутри TCP; по порту TCP понятно, что дальше, например, FTP.
3. **Отображение.** Результат показывается в трёх частях окна: список пакетов (кратко: время, адреса, протокол), дерево полей выбранного пакета и сырые байты. Можно применять фильтры (`tcp`, `ftp`, `tcp.flags.syn==1`), отслеживать поток TCP, строить графики и статистику.

**Диссектор** — это модуль-разборщик для конкретного протокола. Он знает формат протокола, раскладывает байты на понятные поля (адреса, порты, флаги, команды) и передаёт оставшиеся данные следующему диссектору.

## 12. Какие есть ограничения? Почему не всегда видно содержимое данных и весь трафик сети?

**Не видно содержимое:**
- если трафик зашифрован (SSH, HTTPS/TLS, VPN), без ключей видны только заголовки, адреса и объём, а данные — нечитаемый шифртекст. В работе это было с SSH (рисунки 16 и 17).

**Не виден весь трафик сети:**
- коммутатор отправляет на порт компьютера только кадры, адресованные этому компьютеру, и широковещательные. Чужие разговоры до нас просто не доходят;
- чтобы видеть чужой трафик, нужно захватывать прямо на нужном узле или настроить зеркалирование порта (SPAN) на коммутаторе;
- в Wi-Fi нужен специальный режим адаптера (monitor mode), и он есть не у всех адаптеров.

**Другие ограничения:**
- нужны права администратора для захвата;
- при большом трафике программа может не успевать и терять пакеты, а файлы записи быстро растут;
- Wireshark только показывает трафик, а делать выводы (нормальный обмен или атака) должен сам специалист.

При установке TCP-соединения отправляется пакет SYN и возможны три варианта:
1. Пакет с флагами ACK и SYN, указывающий на то, что компьютер присутствует и по данному порту может установлено соединение
2. Пакет с флагом ACK и RST - компьютер присутствует, но порт не открыт
3. Компьютер недоступен - ответа нет

## TCP-сканирование с флагами 
Метод сканирования TCP-портов с флагом: 
- SYN - атакующий отправляет на порт SYN пакет: *вверху написано*
- FIN - по стандарту протокола TCP на FIN-пакет на закрытый порт сервер должен ответить RST-пакетом, на открытом порту такой пакет игнорируется
- ACK - как FIN
Методы сканирования XMAS и NULL
  
На UDP порт, паке состоящий из нулей:
- порт открыт -> ответный UDP-пакет
- порт закрыт -> ICMP-сообщение с кодом 0x03 (Port Unreachable)
